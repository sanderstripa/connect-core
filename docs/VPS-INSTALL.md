# CONNECT Core: установка VPS

На Linux VPS с systemd, публичным IPv4 и `/dev/net/tun`:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | bash
```

Требуются root/sudo. Скрипт разрешает main в точный SHA и собирает согласованные
Core, control API, UI и ACME helper в seekable-каталоге. Новая установка генерирует
пароль и после HTTPS-входа и внешней проверки печатает ссылку, admin и пароль.
Реквизиты не передаются по открытому HTTP. Ошибка проверки означает неуспех и откат.
Повторная команда обновляет проверенную собственную установку, сохраняя пароль,
устройства, CA и отзывы сертификатов. Чужие каталоги не принимаются под управление.

## Любой свободный порт панели

По умолчанию ищется свободный TCP-порт от 17890. Явный подходящий порт 1..65535:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | bash -s -- install --panel-port 24443
```

Для уже установленной панели:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | bash -s -- update --panel-port 24443
```

`--panel-port 0` выбирает свободный порт автоматически. Сама смена порта меняет
только HTTPS UI и точные собственные правила входа, проверяет новый адрес и при
обычной ошибке возвращает прежнюю конфигурацию. Core/TUN из-за смены порта не
перезапускаются; обновление бинарников Core перезапускает собственные Core/UI.
Пример ссылки: `https://PUBLIC_IP:24443/`. Порт панели не ограничивает скорость
VPN: транспорт использует отдельный UDP-порт, обычно 17444. API остаётся локальным.

## Сертификат и соседи

Для автоматического доверенного IP-сертификата ACME требует свободный 443
(TLS-ALPN-01) или 80 (HTTP-01). Это временный проверочный слушатель, независимый
от порта панели. Точное временное правило удаляется после проверки. HTTP-01
обслуживает challenge, а пароль передаётся только по HTTPS. Работает таймер renewal.
Службы Xray/Sudoku/MIST и другие владельцы портов не останавливаются.

Если оба стандартных порта заняты, можно явно предоставить уже доверенный
сертификат с IP SAN и соответствующий ключ:

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | bash -s -- install --panel-port 24443 --tls-cert /absolute/fullchain.pem --tls-key /absolute/key.pem
```

Источники только читаются. Копия сохраняется в защищённом хранилище CONNECT;
проверяются цепочка доверия, IP SAN, срок и соответствие ключа. Источник продлевает
его владелец; таймер CONNECT подхватывает действующую пару. Доменный сертификат
без IP SAN не заменяет сертификат для IP. Самоподписанная подмена и `curl -k`
не используются. При невозможности получить/проверить сертификат установка
не сообщает об успехе и не отключает соседние службы.

## Windows

Войдите в панель → создайте новую одноразовую ссылку → распакуйте весь Windows ZIP
→ запустите ConnectCore.exe → Ctrl+V → Подключить. Ключ создаётся локально и
защищается DPAPI. Новая ссылка автоматически разрешает первый подписанный запрос.
Ручного DNS и отдельного одобрения новых ссылок нет. Windows UAC разрешает работу
ограниченного сетевого помощника. Старые приглашения сохраняют прежнюю политику.

Пустые, слишком короткие и превышающие MTU пакеты Wintun отбрасываются без
закрытия VPN-канала. Некорректные управляющие команды по-прежнему завершают
канал и сохраняют защитную блокировку до явного восстановления.

Временные таймауты старта и занятая прежняя QUIC-сессия повторяются с ограниченным
backoff до 30 секунд. Ошибки сертификата и отзыв доступа не обходятся. Диагностика
с UTC-временем сохраняется между запусками в
`%LOCALAPPDATA%/ConnectCoreLab/diagnostics.log`; ключей и токенов в ней нет.
Прямого обхода при сбое нет; для сохранённой защиты предусмотрено восстановление F10.

Пакеты разных IP-потоков обслуживаются по очереди, с сохранением порядка внутри
каждого потока и общего ограничения памяти. Короткий новый поток имеет небольшой
резерв при заполнении очереди большой загрузкой. Политика адресов и отзыв доступа
проверяются как прежде. Размер очереди Linux TUN отделён от планировщика приложения.

Диагностика разделяет отбрасывания по политике, ёмкости очереди, отсутствию активной
сессии и кольцу Wintun; счётчики потерь полные. Времена ожидания в очередях, QUIC,
TUN и pipe измеряются на одном пакете из 64, чтобы сами измерения не тормозили
передачу. Отчёты выводятся каждые 30 секунд и при завершении; `max_us` относится
к измеренным образцам. Расход CPU собственных worker/helper выводится отдельно.

## Границы

CONNECT создаёт собственный cc-vps0 и точные firewall/NAT правила. Чужие маршруты,
DNS, правила и службы не изменяются. Глобальный ip_forward не меняется: forwarding
включается на TUN и выбранном uplink с условным откатом. Очередь настраивается
только у интерфейса с совпадающим журналом владения.

CI проверяет настоящие ACME/Pebble, HTTPS-вход с отдельного namespace, регистрацию,
QUIC/TUN, произвольный порт, соседей 80/443, renewal, update/rollback и native окно
 Windows. Скорость сравнивается с 0.2.5 на одном shaped-маршруте при RTT 0/80 мс,
включая ограничение 40 Мбит/с и одновременные замеры задержки. Windows UDP-компонент
с отражателем в памяти проверяется отдельно от настоящего Windows → Linux TUN
TCP-сценария; в первом нет Linux/VPS, во втором скорость может ограничивать TCG.
Нагрузочные замеры отделены от полных захватов исходных сценариев безопасности.
Компонентные и CI-цифры не являются обещанием скорости публичной VPS.
IPv6 в системном режиме блокируется; IPv6-туннель и boot-time isolation не заявлены.
Действующие Amsterdam/Denmark и основной Windows агентом не изменяются.

UDP-сокет CONNECT создаёт systemd с отдельными буферами 8 МиБ и передаёт
непривилегированному Core. Установка проверяет фактические размеры; глобальные
net.core.rmem_max/wmem_max не меняются, CAP_NET_ADMIN Core не получает.
Обновление старой установки переносит только собственную службу; при ошибке
возвращает её прежний unit. Возврат с этой схемы на 0.2.4 и старше отклоняется
до остановки служб, поскольку те версии не понимают переданный сокет.
