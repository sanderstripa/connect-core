# CONNECT Core 0.2.1: автоматическая установка с публичным HTTPS

На Linux VPS с systemd и назначенным публичным IPv4 выполнить одну команду:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | sudo bash
```

Адрес сервера не зашит в скрипт. Установщик определяет IPv4/uplink, выбирает
свободные порты и отдельную /24, закрепляет полный SHA main, собирает сервер,
ядро и веб-панель. На apt-based системе устанавливает только недостающие
зависимости; apt upgrade не выполняется. Если Go отсутствует, проверенный по
официальному SHA256 toolchain скачивается во временную папку.

Никаких запросов создания/повтора пароля и интерактивного подтверждения установки.
Случайный пароль admin генерируется из 24 криптографически случайных байтов.
После успешных проверок терминал обязательно показывает:

```text
Panel: https://SERVER_IP
Login: admin
Password: GENERATED_PASSWORD
```

При занятом 443 выбирается свободный 80, тогда URL — `https://SERVER_IP:80`.
Это HTTPS даже на порту 80. Если оба порта заняты, установка отказывает, не
останавливая их владельцев. Публичный IP-сертификат требует ACME-проверки на
443 (TLS-ALPN-01) либо 80 (HTTP-01); произвольный свободный высокий порт не
заменяет эту проверку. HTTP-01 выдаёт только challenge, никогда форму входа или
пароль. Дополнительный порт для сертификатов не открывается: используется
тот же выбранный порт панели.

## Сертификат, вход и проверка доступности

Let’s Encrypt выпускает доверенный IP-сертификат shortlived, без домена и
самоподписанного fallback. `connect-cert` использует lego v5.5.2. Сертификат
проверяется по IP SAN, цепочке доверия и сроку действия. Панель обслуживает только
TLS 1.3, cookie — Secure/HttpOnly/SameSite, сохраняются Host/Origin/CSRF проверки.
Административный Core API остаётся на numeric loopback; наружу он не открывается.

Перед выдачей реквизитов проверяются работа Core/TUN, HTTPS-страница, настоящий
вход с сгенерированным паролем и выход из проверочной сессии. Дополнительно
Check-Host выполняет GET публичной HTTPS-панели: требуется HTTP 200 от точного IP
с двух внешних узлов. Пароль, cookie, приглашения и ключи этому сервису не
передаются. При провале ACME, входа или внешней проверки установка не объявляется
успешной; свои службы/сеть/файлы откатываются.

Firewall хоста получает только собственные правила для выбранного порта панели,
data UDP (обычно 17444) и enrollment HTTPS TCP (обычно 17900). Firewall провайдера
без его API-доступа изменить невозможно: если он закрывает эти порты, ACME/
внешняя проверка откажут с ошибкой. Никакой фиктивной ссылки успеха не будет.
Контейнер без systemd/TUN и cloud NAT без локального публичного IP не подходят.

Служба `connect-ui-cert.timer` проверяет сертификат каждый час и продлевает его,
когда осталось меньше 72 часов. Для ACME временно останавливается только
собственная панель CONNECT; ядро и другие VPN не останавливаются. После ошибки
продления панель запускается с прежним сертификатом, ошибка остаётся в systemd.
Аккаунт ACME и его ключ — root-only; новые пары cert/key публикуются атомарно.
Реквизиты также сохраняются в `/etc/connect-core/install-access.json` с 0600
(root-only); панель хранит scrypt hash, не plaintext пароль.

## Первое устройство

Открыть выданную HTTPS-ссылку прямо в браузере, войти как admin с выданным
паролем. SSH tunnel не нужен. Нажать «Добавить устройство», создать invitation
`connect://enroll?...`, импортировать в Windows CONNECT Core через Ctrl+V/F2.
Сравнить весь fingerprint устройства с заявкой в панели и одобрить. Закрытый
ключ создаётся и остаётся на устройстве; Windows хранит его через DPAPI.
Первое системное подключение запросит числовой IPv4 DNS, достижимый через VPS.

## Соседние службы и владение

Установщик не удаляет/не перезапускает Xray, Sudoku, MIST, 3x-ui и чужие службы,
не захватывает занятые аккаунты, unit-файлы, cc-vps0 или каталоги. Собственные
root-журнал, пользователи connectcore/connectui, группа connectadmin, persistent
TUN и scoped NAT отделены от соседей. Чужие цепочки/правила не очищаются.
Глобальный ip_forward не переключается; shared uplink forwarding возвращается
только если другая сеть с момента установки не изменилась. Откат отказывает
при подмене собственных unit-файлов, UID или интерфейса, а не удаляет чужие объекты.

## Обновление, откат, удаление

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/sanderstripa/connect-core/main/scripts/install-vps.sh | sudo bash -s -- update
sudo python3 /opt/connect-core/current/scripts/connect-install.py status
sudo python3 /opt/connect-core/current/scripts/connect-install.py rollback
```

Update проверяет API v1/state v1, создаёт новую сборку отдельно и переключает
symlink атомарно. При провале health возвращаются предыдущие бинарники; CA,
пароль, регистрации и отзывы не восстанавливаются из старой копии.
Установка 0.2.0 при бинарном update сохраняет прежнюю localhost-конфигурацию:
update не публикует старую административную панель молча. Публичный автоматический
сценарий этой версии проверяется для новой установки.

Удаление всей собственной установки, включая ключи и устройства, с подтверждением:
`sudo python3 /opt/connect-core/current/scripts/connect-install.py uninstall`.

## Граница доказательств

Одноразовый CI проверяет piped installer без TTY, генерацию/вывод реквизитов,
реальное IP ACME challenge через Pebble, TLS trust/IP SAN, доступ с отдельного
network namespace, вход/создание устройства/QR/CSR/approval/QUIC/TUN, renewal,
ошибки доступности, update/rollback и точное сохранение соседней службы/правил.
Test CA и peer override запрещены для публичного IP и доступны только на явно
opted-in disposable CI; production использует system trust и внешние узлы.
Эти проверки не выдаются за field trial публичной VPS. IPv6 туннеля нет;
сертификаты устройств требуют контролируемого продления, сохраняются прежние
ограничения desktop/boot-time isolation.
