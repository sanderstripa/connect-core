# CONNECT Core: результат продолжения разработки

14 октября 2026 года. Работа выполнена в существующем sanderstripa/connect-core.
Изменения опубликованы в ветке connect-ip-v2-lab, PR:
https://github.com/sanderstripa/connect-core/pull/1

## Что теперь работает

Добавлен CONNECT IP v2: отдельный пакетный формат с согласованием сессии,
проверкой устройства и передачей IPv4 через QUIC DATAGRAM. Криптографию выполняют
TLS 1.3 и quic-go; собственных шифров, ключевого обмена или nonce-схем нет.

Реальная цепочка Linux:

приложение → TUN клиента → CONNECT IP v2 / QUIC / mTLS → TUN сервера →
маршрутизация Linux → отдельная тестовая сеть с TCP, UDP и DNS.

Она проверена в трёх одноразовых Linux network namespaces. Передаются HTTP,
двоичные данные TCP, восемь одновременных TCP-потоков, UDP и DNS-пакеты. Проверены
TCP half-close, запрещённое назначение, аварийная остановка сервера, отсутствие
прямого обхода туннеля и захват внешнего для туннеля интерфейса.

В отдельной одноразовой Windows CI-машине установлен официальный подписанный
Wintun, создан новый адаптер, настроены только его адрес, MTU и узкий /32 маршрут.
Запрос UDP/53 из обычного Windows-сокета прошёл настоящий Wintun, QUIC/mTLS,
серверный пакетный стенд и вернулся через Wintun корректным DNS-ответом. Тест
выполнен с обнаружением гонок. Это проверка Windows-пути, а не утверждение, что
Windows уже соединилась с Linux VPS: серверная часть этого Windows-теста —
пакетный стенд. Полный Linux kernel/TUN-путь проверяется другим CI-заданием.

Устройства получают заранее назначенные адреса по отпечатку проверенного
сертификата. Сервер отклоняет подмену источника и повторный захват адреса.
Ответы направляются владельцу адреса через ограниченную очередь. Проверена
изоляция двух устройств. Конфигурация разрешает только частные тестовые
endpoint и сети /24 или уже, исключая endpoint и адреса устройств из назначений.
IPv6, фрагменты, опции IP, некорректные длины/контрольные суммы и слишком большие
пакеты отклоняются. MTU первого этапа — 1100 байт.

Старый локальный TCP v1 сохранён с прежними командами и форматом. Его проверки
также проходят. Код остаётся в том же модуле и репозитории.

## Актуальное исследование

Официальный Xray v26.10.10 подтверждён: опубликован 10 октября 2026 года в
09:22:39 UTC, то есть 14:22:39 по Екатеринбургу. Статус — prerelease. Тег указывает
на 701af60772cda123492f86e383e1fdba066614a9. Изучены именно закреплённые исходники,
релиз и официальное сравнение с 26.3.27; тело релиза не содержит полноценного
changelog, поэтому изменения не выдуманы из его названия.

Существенные исправления прежних предположений: актуальный Xray имеет собственный
TUN, MASQUE/CONNECT-IP с H3/H2, Windows WFP-фильтры, дополнительные меры обхода
проблем Windows-маршрутизации, гибридное VLESS-шифрование и Sudoku finalmask.
Последний прямо обозначен upstream как преобразование внешнего вида без своего
handshake. Динамические WFP-фильтры снимаются при смерти процесса: одно их наличие
не доказывает постоянный kill switch.

26.3.27 оставлена в исследовании только как подтверждённый факт старой упаковки
приложения CONNECT.: его scripts/engines.ps1 всё ещё скачивает этот бинарник.
Новое исследование автоматически не обновляет другое приложение и его профили.
В самом CONNECT Core Xray не является зависимостью: закреплена версия исследования,
а не выдуманный используемый движком Xray-бинарник.

У Sudoku подтверждён актуальный официальный v0.5.1 от 25 сентября 2026 года.
Его тег и main совпадают по исходному коммиту 4889b53; панель Sudoku UI закрепляет
тот же upstream и добавляет патч доступа. Отдельно изучены KIP, ephemeral X25519,
HKDF, направления ключей, AEAD-записи, nonce/sequence, обновление ключей и replay.
Таблицы, padding и HTTP-mask — другой слой. Идентификатор UserHash сам по себе
не доказывает владение индивидуальным ключом; CONNECT использует отдельные mTLS
сертификаты и подтверждение владения ключом библиотекой TLS.

У MIST изучена ветка mist-hardening-32 и её исходный коммит d4e7dacf, а также
актуальная модифицированная копия движка в MIST UI 13cfd64b. Рассмотрены TUN/Wintun,
HTTP/3 datagrams/CONNECT-IP, надёжные H3 lanes, H2 fallback, MTU, авторизация,
маршрутизация ответов, ограниченные очереди и проверки адресов.

## Какие механизмы применены

| Источник | Что применено в CONNECT |
| --- | --- |
| Xray | Разделение движка, транспорта и политики; явные возможности; отказ вместо ослабления безопасности. Урок настройки MTU/готовности Windows IP применён в изолированном Wintun-стенде. |
| Sudoku | Разделение ключевого обмена/AEAD/replay и маскировки; требование отдельного доказательства владения ключом устройства. Ключи и replay реализует TLS/QUIC, а не скопированный KIP. |
| MIST / MIST UI | Пакетный TUN-путь; отдельное управление и датаграммы; назначение адреса; проверка источника; маршрутизация ответов по адресу и ограниченные очереди устройств. |

Исходники этих трёх движков не скопированы и не слинкованы. Собственный CONNECT
протокол определяет сессию, назначение адреса и допустимость IP-пакетов; стандартные
библиотеки обеспечивают криптографию и транспорт. Такой подход позволяет развивать
движок без переноса трёх расходящихся кодовых баз и без заявления, что новое
сочетание автоматически безопаснее или быстрее всего существующего.

Анализ вариантов, угроз, совместимости, лицензий и критериев находится в
[DECISIONS.md](DECISIONS.md), подробное исследование —
[IMPLEMENTATION-AUDIT.md](IMPLEMENTATION-AUDIT.md).

Четыре задания CI для кода 08fc5c44052c64bc6460ec43dd9647c431ae64e5 завершились
успешно: Windows, Linux, настоящий Linux TUN-стенд и настоящий Windows Wintun-стенд.

Есть проверка гонок, fuzzing IP и управления, неверной CA/имени/сертификата,
отсутствующего и неразрешённого сертификата, несоответствующего закрытого ключа,
неверного ALPN/назначенного адреса, подмены адреса, повреждённых сообщений,
межустройственных ответов, остановки и повторных подключений.

## Что ещё не сделано

Нет общей проверенной сессии Windows → отдельная Linux VM/VPS, интернет-маршрутизации
и NAT, системной настройки DNS, полного Windows kill switch, IPv6, PMTU и
фрагментов, HTTP/2 fallback, REALITY/XHTTP/Sudoku-маскировки, горячего отзыва ключей,
активного контроля истечения сертификата или 24-часового soak-теста. Блокировка
UDP сейчас означает отказ; прямого обхода нет. Независимой криптографической
экспертизы состава CONNECT пока нет.

Реальных адаптеров к CONNECT. и панели CONNECT UI также нет. Сохранены отдельный
исполняемый движок, совместимый TCP v1, строгий v2 профиль и документированный
контракт будущей интеграции. Старые профили Xray/Sudoku/MIST не переименованы.

Лицензии разобраны явно: Xray MPL-2.0; Sudoku GPL-3.0-or-later с дополнительным
условием на название; MIT панели не перелицензирует Core; у изученной отдельной
MIST-ветки нет корневой LICENSE. Используемые новые библиотеки имеют закреплённые
версии и MIT/BSD notices. Официальный Wintun DLL имеет отдельные условия; он не
включён в результат и не выдан за MIT-библиотеку. Общую лицензию репозиторию
самовольно не назначал.

## Следующий конкретный этап

Сначала — общая Windows VM → Linux VM с теми же TCP/UDP/DNS-проверками и захватами.
Затем — контролируемые задержки/потери, час и сутки стабильности, устройства
1/8/32, прямой baseline и одинаковые условия для других движков. После этого —
помощник маршрутов/DNS/firewall с журналом и откатом, crash-safe блокировка утечек
и интеграция в CONNECT./CONNECT UI. Инструкция уже подготовлена в IP-LAB.md.

Переход к тестовому VPS требует отдельно выбранного изолированного сервера и
согласования конкретных изменений. Ни Амстердам, ни работающие Xray/Sudoku/MIST
на датском VPS не открывались и не менялись.

Изменения доступны в ветке и PR. Прямая запись в main была отклонена автоматической
проверкой как действие без явного разрешения на основную ветку; поэтому до
отдельного разрешения результат оставлен в проверяемом PR, а main не обновлена.
